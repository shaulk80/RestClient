    Bug found in manual testing and fixed:
    - Switching tabs marked the target tab as changed. The tab content view is reused, so the combo boxes (method,
      body type, auth type, API key location) got a new item list from the new tab, and wrote their old selection
      into it. This changed the value as well as the flag. The lists are now shared by all tabs.
      MainWindowSmokeTests.SwitchingTabsKeepsCleanTabsClean covers it with tabs of different method, body and auth.

    Deviations from plan and open points:
    - TabService does not track open and dirty state. That stays in the tab view models (TabStripViewModel owns
      the list). TabService stores and restores the list: a snapshot of every tab, with a draft for each tab that is
      dirty or not linked. The plan's "open, close, dirty tracking" is done in the UI layer.
    - OpenTab, TabSnapshot and RestoredTab are Application records. The plan said no new types beyond AppSettings.
    - A restored tab whose request was deleted keeps its draft as an unsaved tab. Without a draft it is dropped.
      A restored linked tab takes its name from the collection, and its content from the draft.
    - Closing any dirty tab asks to save, not only unsaved ones. Drafts are stored, but closing a tab discards its draft.

    - A tab that sends while it is closed is cancelled.
    - Settings: timeout 1 to 3600 s, redirect limit 1 to 50 (kept when redirects are off), proxy empty (system proxy)
      or an absolute http, https or socks URL. A stored value that cannot be read falls back to its default.
      A proxy with credentials is not supported.
    - RequestBuilder takes ISettingsService, not a fixed timeout. RequestBuilder.DefaultTimeout is gone
      (AppSettings.Default.Timeout replaces it). HttpTransportOptions is built from AppSettings on each send.
    - RequestHttpClientFactoryTests are not a separate class. SocketsHttpHandler cannot be inspected without
      reflection, so the settings are tested through real requests (Integration SettingsAppliedTests: redirects,
      redirect limit, timeout, SSL against a self-signed HTTPS server, proxy).
    - Turning SSL verification off disables all certificate checks (CA5359 is suppressed on RequestHttpClientFactory.Create).
