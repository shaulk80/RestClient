    Deviations from plan and open points:
    - Domain body and auth types are all defined now (plan section 4). The builder returns a
      Validation error for form, multipart, and non-none auth until M4 and M5 implement them.
    - VariableResolver takes a plain dictionary. Environments and secrets arrive in M5.
    - Timeout is a fixed 30 s default (RequestBuilder.DefaultTimeout). Settings come in M6.
    - Redirects are fixed at follow, up to 10, in DI (HttpTransportOptions). Settings come in M6.
    - Each send creates its own HttpClient so the connect callback always sees a new connection.
      Connection reuse is not in M1.
    - Spill threshold is 1 MB, not 5 MB (decided 2026-10-24). Bodies up to 1 MB are kept in
      memory in full. Larger bodies are written to a file, and the preview is their first 1 MB.
      Plan section 9 and architecture plan Q9 are updated.
    - Spilled bodies go to data/temp/ and are not cleaned up. Cleanup moved to M3 and done there.
    - UI has a Content-Type box, which the plan does not list. Headers and query params are
      supported by RequestBuilder but have no editor in M1.
    - RequestSender does not record history (M3).
    - Sample API for tests: tests/RestClient.SampleApi (ASP.NET Core minimal API on
      http://localhost:5080). GET /api/hello returns a fixed text response. POST /api/echo
      returns the request body with its Content-Type. Not production code. It will be extended
      for fine-grained tests.

    Deviations from plan and open points:
    - HistoryEntry has a BodyFilePath field. The plan's field list does not have one. It lets retention delete
      the spilled body files of expired entries, which is the cleanup deferred from M1.
    - The request snapshot reuses RequestDto and RequestJson. No separate RequestSnapshotDto was added,
      because the shape is the same.
    - Restore opens an unsaved tab with the snapshot, under a new identifier. Nothing is written to a
      collection until the user saves (PLAN CHANGE 2026-10-25). The first version saved a copy at once.
      That made every restore add a request to the tree.
    - Validation failures are recorded too. Their URL is the URL as typed, because no URL was built.
    - A history write that fails does not fail the send. The repository logs the error. The UI does not show it.
    - History writes are serialized in HistoryService. Retention loads all entries on each insert. That is
      fine for up to 1000 entries. Revisit if it gets slow.
    - Search is a case-insensitive URL substring (ASCII case folding) plus an exact method. The method
      list starts with "Any method".
    - Spilled bodies are deleted only when their entry is removed, and only inside data\temp. A path
      outside that folder is refused with a Security error.
    - Domain line coverage fell to 90.74% (from 95.61% at M2). The new HistoryEntry record has no
      logic, but its generated members count as lines. Still above the gate.
    - Sent time is stored as Unix milliseconds.
    - Open: saving into a folder where the name is taken gives "Login 2" with no warning. The save dialog
      does not check names. Carried to M7 as a polish item.

KNOWN ISSUES AND NOTES
----------------------
- The release zips include .pdb files (about 100 MB uncompressed). Consider
  DebugType=none for release publishes; not changed yet.
- Startup errors (data folder cannot be created, migration fails, or an unhandled exception
  before the window opens) are written to stderr only. The Windows build is a GUI app with
  no console, so the user sees nothing. Deferred to M7: show a visible error dialog.
- Spilled bodies in data/temp/ are deleted when their history entry is removed by retention (M3).
  Bodies of responses whose history entry is still kept stay on disk until then.
- Integration and UI test projects contain M1 tests. Headless UI smoke tests come with M6.
