    - Form and multipart bodies are built by RequestBuilder now (M1 returned a Validation error for them).
      RequestBuilder.Build is BuildAsync, because file parts are read through IFileReader (plan 5.1).
    - Multipart file parts are read fully into memory before the send. A large upload uses memory equal
      to the file size. Streaming is not in M4.
    - Every file part is sent as application/octet-stream. No MIME mapping by extension.
    - The multipart boundary comes from IIdGenerator ("RestClientBoundary" plus 32 hex digits).
    - Formatting empty text gives a Validation error ("There is no body to format."). Parser messages

      handled.
    - Form field names and multipart part names must not be empty, and a file part needs a path. A blank
      row blocks the send until it is filled in or removed. This matches headers and query params.
    - A response that is not valid JSON or XML shows the raw text with a note ("Pretty print failed: ...").
      That covers truncated previews of large bodies.
    - The saved body is the selected type only. Values for other types stay in the editor until the tab closes.
    - Headers and query params still have no editor. That stays out of M4, as in M1.
    - Records with list fields compare lists by reference, so tests compare Fields and Parts element by element.
    - CodeEditor has a headless test (text sync and language switch). View-level headless smoke tests stay in M6.

    Deviations from plan and open points:
    - The plan's Environment type is RequestEnvironment. Environment clashes with System.Environment in
      files that import both.
    - Secrets are stored as ciphertext in Variable.Value. The editor sends a typed secret as VariableEdit
      with ValueIsPlainText, and EnvironmentService encrypts it. Plain text never reaches the repository.
      The secret_value column holds ciphertext, and value is NULL for a secret (tested).
    - A secret is decrypted only when the request names it (RequestPlaceholders covers URL, parameters,
      headers, body and auth). A locked secret blocks only the requests that use it.
    - IRequestSender lost its variables argument. RequestSender gets the variables from IRequestVariables,
      so a failed lookup is recorded in history as an attempt. The UI tests were updated.
    - After a locked-secret failure and a successful unlock, the request is sent once more. The locked attempt
      stays in history as its own entry.
    - SecretService keeps the salt, the iteration count and an encrypted verifier in the settings table.
      The iteration count is 600,000, as in plan section 9, and is stored with each setup.
    - The active environment is stored in the settings table too.
    - Workspace<T> is a generic version of CollectionWorkspace's load-and-save logic. CollectionWorkspace was
      not changed to use it. Merge them in M7 to remove the duplication.
    - Auth headers replace a header of the same name that the user wrote, as Content-Type does.
    - Environment names are unique, ignoring case. Variable names are unique after trimming and cannot
      contain braces.
    - Secret rows: a stored secret shows no value, and typing one replaces it. Turning Secret off clears the value,
      because the ciphertext has no plain form.
    - The app does not lock on a timer. Locking happens on Lock, on exit, and by the user.
    - Open: a corrupt salt or iteration setting throws FormatException when unlocking, because it is not caught
      in the Application layer (which has no logger). Fix it in M6, when the settings store gets typed values.
    - Open: request headers and query params still have no editor (carried from M1 and M4).
    - Open: the Application coverage fell from 95.83% to 92.42% because of the new services. The gate holds.
    - Note: scripts\build.ps1 fails while a sample API process holds tests\RestClient.SampleApi\bin\...\apphost.exe.
      Close the sample API before running it.

KNOWN ISSUES AND NOTES
----------------------
- The release zips include .pdb files (about 100 MB uncompressed). Consider
  DebugType=none for release publishes; not changed yet.
- Startup errors (data folder cannot be created, migration fails, or an unhandled exception
  before the window opens) are written to stderr only. The Windows build is a GUI app with
  no console, so the user sees nothing. Deferred to M7: show a visible error dialog.
- Spilled bodies in data/temp/ are deleted when their history entry is removed by retention (M3).
  Bodies of responses whose history entry is still kept stay on disk until then.
- Integration and UI test projects contain M1 tests. Headless UI smoke tests come with M6.
